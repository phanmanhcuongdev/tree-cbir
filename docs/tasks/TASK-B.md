## Mission and starting point

Deliver shared canopy ROI, foliage and branch measurements, plus a versioned ingestion and storage path for the accepted corpus and one frozen normalization fit. Provide the populated database and setup/replay instructions for C's demonstration.

Canopy/branch segmenters and calculators, `database.py`, `normalization.py`, `services/dataset.py` and `scripts/build_dataset.py` are placeholders. P02's standardized 507 candidate images and review remain the foundation. `sql/01_init.sql` enables pgvector and the existing integration test verifies a temporary `vector(38)` table and distance operations, with production schema, valid-only fit and batch ingestion still pending. The audit records no accepted canopy/branch research baseline. P02 generic masks are preprocessing examples. Use them for utility examples only. [Audit](../team_preparation/repository_audit.md) · [Database design](../database.md)

Reuse RGB preprocessing, color/geometry/morphology/edge helpers, existing component contracts and `synthetic_tree_factory`. Difficult cases include leafless versus unknown foliage, low-chroma/wrap-around hue, sky/background leakage, cropped canopies, and woody lines close to foliage or the background. Do not infer branch complexity from X17 alone. The database must keep validity, schema/fit versions and manifest consistency independently of algorithm quality.
