## Mission and starting point

Deliver a reproducible trunk observation and the canonical X0–X8 calculations. Integrate all five groups under one versioned extraction profile usable by both ingestion and queries. Coordinate the final integration regression and combine evidence supplied by all three packages.

`segmentation/trunk.py` defaults to the frozen AUTO hybrid. `features/trunk.py` is a prototype with acknowledged differences in X7/X8 and unresolved height, color and validity. `extractor.py` is a placeholder. `component_contracts.py` already validates and assembles groups and isolates calls. Preserve the existing AUTO/V2/V3 outputs, configurations and checkpoints, including legacy runner behavior for reproducibility. [Audit and recovery paths](../team_preparation/repository_audit.md) · [P03 log](../logs/P03.md)

Reuse hybrid localization, candidate scoring and refinement, `trunk_measurements.py` for legacy provenance, observed geometry and mask helpers, `run_component`, `assemble_feature_groups`, and P02 preprocessing. For a justified V3 continuation reuse `annotations.py`, `superpixels.py`, `superpixel_labels.py`, `region_features.py`, `services/trunk_dataset.py` and `scripts/prepare_trunk_dataset.py`. That foundation contains SLIC, curation and 96 handcrafted per-region features. A production classifier, trained weights and V3 inference are still pending. Its internal region descriptors stay outside X0–X37.

AUTO hybrid achieved 4/6 usable on calibration and 3/12 on the independent qualitative set, below its 5/6 and 9/12 targets. Structural trim lost a calibration case. V2 iteration 10 underperformed hybrid on the independent V2 set (2/24 versus 4/24 usable). Wide, occluded and short trunks or competing background structure pose known risks. Keep datasets, rubrics and metric versions attached to every result. Use the V3 train/validation split only for development if selected, with saved manifest and labels. V2's old C set is historical evidence and partly included in V3 development. Protect the separate frozen V3 holdout.

## Stage I — Independent development

- [ ] **TA-01** Recover and record the hybrid baseline and artifact/version IDs. Use existing candidate and localization code as the first option. Inspect the frozen source/evidence via the audit and decide which production comparisons are meaningful on development data.
- [ ] **TA-02** Implement canonical X0–X8 measurement on synthetic known masks. In particular, X7 is the median run count in the 15–60% basal band and X8 counts junctions in the lower trunk. Keep bark and expected-height-dependent values versioned and gate unresolved production semantics. Cover span, curvature, clipping, valid zero and rejection of unreliable metadata.
- [ ] **TA-03** Bridge legacy trunk results into the shared types without promoting provisional expected height or legacy pixel-count widths. A candidate V3 classifier must be trained on group-owned development data, with no pretrained model, leakage or production ground-truth dependency. Compare behavior and confidence errors before proposing a switch. Keep the historic hybrid reproducible.

Cover out-of-order delivery, failed component containment, version mismatch, finite invalid placeholders, X22 gating and context contamination. Publish the shared interface and tagged decisions for **M1**.
