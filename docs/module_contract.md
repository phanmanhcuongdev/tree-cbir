# Shared module contracts — 03/08

The shared boundary is implemented in `src/tree_cbir/component_contracts.py` and reuses `RGBImage`, `BinaryMask`, `SegmentationResult` and `FeatureExtractionResult` in `src/tree_cbir/models.py`. Feature meanings and quality decisions live in the [feature specification](feature_spec.md) and [decision register](team_preparation/specification_decisions.md). The signatures below specify data exchange for future implementations. They do not advertise algorithm entry points that still need implementation.

## Canonical representations

| Item | Contract |
| --- | --- |
| Image | NumPy `uint8` RGB with shape `(1024, 768, 3)`. P02 returns contiguous arrays. The boundary checks shape and dtype. Explicitly convert RGB to BGR if calling an OpenCV operation that expects BGR. |
| Mask or ROI | NumPy bool with shape `(1024, 768)`, aligned to the image. `True` is membership. Missing means the key is absent. An empty mask has no foreground and still requires a status to distinguish absence from uncertainty. |
| Point | `(x, y)` in pixel-center coordinates, origin upper left. Integer pixel indices or finite subpixel coordinates in bounds. Modeling coordinates are `(x, y)` while array access is `[y, x]`. |
| Bounding box | `(x, y, width, height)` in integer pixels, positive sizes and within the canonical image. The covered slice is `[y:y+height, x:x+width]`. A box at `(767, 1023, 1, 1)` is valid. A missing box is `None`. Box width and X4's coordinate span are separate measurements. |
| Feature values | `float64` vectors with one bool per position. Counts can be integral in meaning with float64 storage. Ranges/units are in the feature spec. Missing features use finite `0.0` and `False` in the assembled record. A measured zero uses `True`. |
| Measurement | `Measurement[T](value, quality)` uses `measured`, `estimated`, `unreliable` or `unavailable`. `None` is paired with `unavailable`. An estimated/unreliable value can be retained for diagnostics and for explicitly allowed fallback behavior. |
| Segmentation state | `ComponentState(status, confidence, version)` uses `SegmentationStatus`. `RELIABLE_DETECTION` is a supported positive observation, `PARTIAL_DETECTION` has partial usable evidence, `UNCERTAIN_DETECTION` is inconclusive, `CONFIRMED_ABSENT` is an inspected empty observation, `UNAVAILABLE` means no usable result was supplied, and `FAILED` is an isolated error or rejected output. `confidence` is optional and bounded to `[0,1]`, a heuristic score. `FAILED` and `UNAVAILABLE` have no confidence. |
| Version identity | `AlgorithmVersion(algorithm, revision, config_version)` identifies the component implementation and reproducible configuration. A component that ran has a version. An omitted component has none. Use a registry or stable configuration digest for `config_version`. Include segmentation method/checkpoint if applicable, feature measurement choices, calibration, and versions of numerical dependencies where these affect results. |

### Serialization and compatibility

- Serialize points and boxes as JSON arrays in the defined order and enum values as strings. Serialize unavailable measurements, confidence or versions as `null` with appropriate state fields. Store finite JSON numbers, not NumPy scalars or NaN/Infinity. Treat masks as separate keyed mask artifacts or bool arrays and preserve their grid. Missing mask keys and zero-area artifacts retain distinct meanings. Record both segmentation and feature diagnostics with explicit observation or dependency reasons.
- Store the raw vector and bool validity as separate fields in canonical order. Persist an extractor/feature-profile version and a normalization fit ID with the indexed vectors. Map the five group slices by `FEATURE_GROUP_SLICES`. Normalize or compare only compatible feature versions. No serializer, DB schema, model registry or production loader is implemented in 03/08.
- Keep calibration numeric values in module-local typed configuration. The trunk profile identifies its expected-height estimator and bark representation. The canopy profile identifies the hue scale and averaging convention. The branch profile has separate `visibility_threshold` and `skeleton_length_threshold` fields. The context profile records the exclusion policy and lower ROI provenance. Keep the distance, weights and minimum coverage in a separate versioned ranking profile. Derive or assign `config_version` after these choices are recorded. Missing required settings are unavailable to the dependent measurement. An experimental profile must identify itself explicitly.
- Core contract arrays are read-only by convention after handoff. The assembler owns new values and validity arrays, and passes mask references. Producers must copy before modifying a referenced array. Frozen dataclasses do not freeze NumPy storage.
- Legacy `PreprocessedImage` and `SegmentationResult` constructors retain their generic dimension validation. Call `validate_image` and use `ComponentSegmentation` at shared component boundaries. Existing experiments can still use smaller images and masks through their legacy interfaces.

## Executable result types

- `ComponentSegmentation[T](group, state, result, geometry)` wraps an existing `SegmentationResult` with strict dimensions, owned mask keys and typed optional metadata. Reliable detection must include a nonempty primary component mask (for context, ground or background). Confirmed absence explicitly includes an empty primary mask for the four tree groups. Failed or unavailable components have no masks or geometry.
- `ComponentResult[T](segmentation, feature_ids, values, valid, diagnostics)` binds component output to the exact `FEATURE_IDS[FEATURE_GROUP_SLICES[group]]` tuple. The constructor rejects wrong order, repeated/missing IDs, wrong dimensions, wrong dtype and any valid nonfinite value. Unavailable or failed results cannot mark a feature valid. Per-feature reasons can go in `diagnostics`, alongside other feature evidence.
- `run_component(group, rgb, version, operation)` validates the shared input, then calls the explicitly registered operation. Bind optional upstream inputs and versioned algorithm configuration in the supplied callable. An exception raised by the operation records `FAILED`, the version, and the exception class. It leaves that slice invalid without swallowing process-level interrupts. A group/version mismatch after a return is a registration error and raises. There is no implicit algorithm or mock fallback.
- `assemble_feature_groups(results)` accepts any order and also accepts partial input. An omitted group receives `UNAVAILABLE`, no version and an invalid slice. Duplicate groups are rejected. Invalid feature positions are filled with `0.0`, yielding a finite DB-ready raw vector with exactly 38 bool flags in the same order. `FeatureExtractionResult.masks` uses unique keys, `diagnostics` is keyed by group and includes nested `features` diagnostics, and `components` carries state and version per group. The legacy constructor remains usable with its original positional arguments. Normalization is separate.

| --- | --- | --- | --- |
| `trunk` | X0–X8 (9) | `TrunkGeometry` | `trunk` |
| `canopy` | X9–X16 (8) | `CanopyGeometry` | `canopy`, `canopy_roi` |
| `branch` | X17–X19 (3) | `BranchGeometry` | `branch` |

## Component boundaries and fallback

The planned segmentation entry points consume the canonical image and a typed, module-owned configuration passed explicitly. Return `ComponentSegmentation` before measuring features. Feature calculators consume that observation and only necessary image/ROI/upstream metadata, then package a `ComponentResult`. The tests can directly supply either observation or result. Use `None` for an optional upstream `ComponentSegmentation` that is missing, or inspect its status, available masks and individual geometry quality when supplied.

| Group | Inputs and outputs | Fallback and guards |
| --- | --- | --- |
| Trunk | RGB and trunk config. Return mask, box, base and upper point, representative width in px, observed and expected heights in px, optional centerline `(x,y)` sequence and bark measurements when representation is selected. Provide quality individually and compute X0–X8 according to the registered profile. | Geometry may be partly observable. Keep estimated height separate and versioned. Lack of a trusted height makes X0 invalid. `segment_trunk` keeps its current signature and `hybrid` default. Future glue must explicitly map `TrunkSegmentation` and `TrunkMeasurements` into the new fields and must verify definitions, e.g. older median pixel count vs. canonical X4 width span. No legacy measurement is silently promoted. |
| Canopy | RGB, optional trunk observation, canopy config. Return `canopy_roi`, foliage mask, `CanopyGeometry.roi_quality` and bounding box quality. Compute X9–X16. | Can supply a separately validated trunk-independent ROI. Tag its origin in diagnostics. If ROI cannot be trusted, visibility is invalid and any other measurements require independently trustworthy foliage evidence. Measured empty foliage may give valid X9 = 0. Geometry and color remain unobserved. The contract checks mask containment when the ROI is supplied. |
| Branch | RGB, selected canopy ROI and its reliability, optional trunk and foliage observations plus branch config. Return visible woody `branch` mask and `BranchGeometry.skeleton` with quality, then X17–X19. | Use an independently corroborated canopy ROI if trunk-guided localization was unreliable. Reuse that selected ROI for canopy and branch to preserve the denominator. If no adequate shared ROI exists, leave X17 invalid and mark X18/X19 valid only if an approved independent observation supplies trustworthy branch topology. When no such observation is available, return an invalid slice. A reliable unbranched skeleton may give valid X19 = 0. Branch validates its mask against the ROI supplied as input. |
| Root | RGB, optional trunk observation (base, positive representative width, mask and approved color), root config. Return `root_roi`, root mask, skeleton and bounding box quality, then X20–X25. | A fallback search ROI can be retained as `estimated`; that alone gives no root detection guarantee. Defer ROI/location-dependent measurements when the base or coverage is uncertain. X22 requires a positive `measured` trunk width using the canonical width definition. The assembler enforces this dependency even if the root producer marks X22 valid. Other root dimensions retain their own validity. Mask containment is checked when a root ROI is present. |
| Context | RGB, available trunk/foliage/branch/root observations and their quality, lower ROI/config. Return `ground`, `background`, optional `lower_roi` and X26–X37, with per-region quality and exclusion diagnostics. | Use the known tree-pixel union including root when selecting regions. A reliable explicit empty observation is evidence of absence, while missing or unreliable regions indicate contamination risk. Producer checks region support and marks affected dimensions invalid unless independent evidence covers missing exclusions under the chosen profile. The assembler flags unresolved upstream states; if a context mask overlaps any returned tree-component mask it fails context, removes its masks, and invalidates X26–X37 without discarding other groups. The context masks must be disjoint and ground must lie inside the supplied lower ROI. |

Recommended diagnostic keys for component producers include `roi_source`, `invalid_features` (X ID to reason code), `ground_quality`, `background_quality` and `contamination_risk` where applicable. The same contract accepts outputs from experiments and production under distinct versions. Keep experimental vectors out of a production index unless their profile is explicitly selected and validated.

## Isolated development and verification

Run from the repository root with the project venv. This command collects only synthetic contract tests. It needs the installed Python dependencies and no dataset or `DATABASE_URL`.

```powershell
.\.venv\Scripts\python.exe -m pytest -v tests/unit/test_component_contracts.py
```

`tests/conftest.py` exposes the pytest fixture `synthetic_tree_factory`. Request it by name in a test and call it for fresh, deterministic arrays. `trunk_case` accepts `complete`, `missing`, `uncertain_base`, or `unreliable_width`. `foliage_case` accepts `leafy`, `leafless` (confirmed empty), or `unknown` (uncertain empty). Set `incomplete_tree=True` to produce a context fixture with incomplete exclusion; the fixture's `tree_mask` retains the full reference union for assertions. The scene includes a synthetic branch skeleton and exposed roots with a root skeleton. Its explicitly test-only version is `synthetic-contract-fixture`, revision `1`, config `test-only`. The production package imports no test fixture. These are deterministic contract inputs and carry no real-image accuracy evidence.

Full regression uses the existing complete test suite with the local database configured as described in the [local 03/08 evidence](../outputs/evaluation/team_preparation_03/validation.md). Some pre-existing tests exercise curated dataset files, independently of the synthetic suite. The local evidence directory is ignored by Git.
