## Evaluation gates and reference semantics

For each `AC-Q-*` gate, supply the common evidence below, the component-specific coverage in this table, and a result against the applicable frozen threshold/profile. Do this separately for development and independent evaluation. Missing qualified references, required case coverage, or an unresolved production quality target blocks the affected verification. Report the available experiments and the actual limitation. An owner-approved `LIMITED` decision has a recorded scope and cannot change a failed metric.

For each component, draw ROI/pixel masks at the canonical grid using a versioned labeling guide, or record the reversible transform from source geometry. Record annotation author ID or authorized pseudonym, time, tool, source-image hash, mask/annotation hash, image ID, component, visibility class, exclusions/ignore mask, and reviewer/adjudication when applicable. Disclose approximate polygons and uncertain boundaries explicitly. Use known provenance with permission. Do not derive independent labels from the predictions being scored. Preserve both the original and corrected annotations with hashes and reasons, and freeze the revision used for scoring.

## Split integrity and leakage prevention

1. Create an immutable source manifest with stable image ID, source SHA-256, standardized SHA-256, standardized dimensions, duplicate/near-duplicate or same-tree group where known, split, prior exposure flags and annotation reference. Hash the manifest and maintain a registry of image exposure. Train, development/validation and independent test are disjoint at image, exact duplicate and known correlated-group level. Report any separation that cannot be verified.
2. Assign all crops, augmentations, tiles, superpixels and region features from one image to that image's split before feature extraction or training. Fit classifiers or tuned thresholds on authorized group-owned training/development data only. Check disjointness by both ID and hash, and publish per-split file, label and feature counts. Never feed evaluation masks, labels, image filenames or expected values to production inference.
3. Freeze the independent list and hashes before viewing outputs for model selection. Before opening independent results, freeze each evaluation profile, annotation version, metrics and applicable thresholds. Store code/commit, algorithm and config, dependencies/model checksum, seeds, split hashes, hardware, commands and parameters. Document deviations and approvals before the run. Reruns after non-algorithmic fixes are identified and justified. Images that informed a later change move to historical/development evidence, and a revised method requires a fresh independent pool for an untouched claim.
4. AUTO calibration and its independent contact-sheet set, and V2's evaluated A/B/C results, are historical. V2 C is already seen and overlaps later P03-FINAL development data. The P03-FINAL V3 metadata records 38 train, 14 validation and a separately frozen 24-image test split. Preserve its sealed status only while the exposure registry supports it. No assumption of adequate independent reference annotations follows from split membership. [Provenance in the repository audit](repository_audit.md)
5. Keep the gallery and unseen query split separate by IDs, hashes and known duplicate groups for retrieval. Fit normalization using only valid observations of the indexed gallery fit corpus. Query cases and held-out relevance judgments are excluded from fitting, ranking configuration selection and annotation-driven runtime decisions.

## Pixel and visibility metrics

- Compute per evaluated image and component on annotated, non-ignored pixels. From predicted and reference bool masks, record TP, FP, FN, predicted area and reference area. Compute IoU = `TP/(TP+FP+FN)`, precision = `TP/(TP+FP)`, recall = `TP/(TP+FN)`, and Dice = `2TP/(2TP+FP+FN)` when their denominators are nonzero. A visible reference and empty prediction has IoU, recall and Dice of zero; precision is undefined. Empty/empty is a visibility outcome and does not count as perfect pixel overlap. Record undefined values as unavailable and give metric-specific sample counts. Include positive-case failures and abstentions in the mask-quality accounting, with separate status-stratified reporting so exclusion cannot improve aggregate results.
- Use reference visibility `visible`, `confirmed absent/non-visible in an inspected region`, or `unknown`. Record prediction state independently. For determinate cases, true detected visible requires positive reference and detection. A correct mask also needs its component quality criterion. True absence needs a verified negative and explicit absence prediction. An erroneous positive or negative is a detection failure. Flag `FAILED`/missing output separately from explicit `UNCERTAIN_DETECTION` or incomplete abstention. Unknown reference cases are reviewed and counted outside determinate metrics. For roots and branches report visible sensitivity with abstentions/failures tracked against the positive denominator, and false-positive counts/area and false-positive image rate on verified negatives. An empty root prediction alone earns no negative success; report the number of verified negatives and the number of positive cases.
- Summarize per-image measures, macro means, median and spread or intervals with denominators and any exclusions. Include visibility counts and absolute FP/FN examples; pooled pixels or global pixel accuracy can be secondary. If landmark/tolerance metrics are used, provide units, positive/eligible sample counts and the tolerance approved before evaluation. Report prevalence and missing predictions, rather than only scores of reliable outputs.
- Review side-by-side original RGB, reference/uncertainty overlay, prediction/ROI, FP and FN overlay, status/confidence and diagnostics. Review all failed or incorrectly reliable cases in the evaluation evidence, and show a reproducibly selected sample of successes, absences and uncertain/difficult cases. Record reviewer, rubric, sample rule and disagreements. Distinguish annotation disagreements from algorithm errors. For each incorrectly reliable example, link the risk reason and record the counts of reliable-correct and reliable-incorrect. A confidence score is a bounded heuristic and must not be described as probability. Report disagreement by status/score band when the sample supports it and include coverage so a method cannot hide errors by declaring everything uncertain.
- Measure wall time on declared hardware, OS, library versions, thread settings and sample count. Warm up on approved development inputs, document cache state and repetition count, and use monotonic timing. For each component and complete pipeline distinguish image I/O, preprocessing, segmentation, measurement, DB/normalization, ranking and rendering as applicable. Report median and p95 plus counts of failures/timeouts. State whether timings exclude loading/rendering and whether results are single-run. Match baseline timing boundaries when comparing performance.

## Retrieval evaluation and demonstration

- A coordinates evidence and acceptance, B publishes the gallery/fit and batch evidence, and C evaluates a frozen profile over an unseen query set. Predefine and version a relevance rubric independent of algorithm output. Record assessor(s), adjudication, the candidate/judged pool and query/gallery hashes, and report coverage of judgments. Measure exact rank agreement with an independent exhaustive calculation separately from relevance.
- With adequate judgments for the declared evaluation set, `Precision@5 = relevant results in five slots / 5`. Record missing slots, unjudged items and treatment of incomplete queries under the frozen protocol. Unjudged results cannot silently become known-negative judgments. Report how many queries are scorable, complete or degraded. `Recall@5` requires a known positive total of relevant gallery items for that query. If judgments are absent/insufficient, report actual query or coverage evidence and withhold unsupported relevance claims.
- Run a complete-vector baseline, per-group/group-removed variants and predeclared weight sensitivity when feasible. Freeze each variant configuration before the held-out comparison; record covered/scorable queries and denominators for each, plus a comparable intersection where useful. Log reasons if ablation or sensitivity cannot be executed. Show examples of context helping or overwhelming morphology, failure cases and no/insufficient overlap. Never tune the final weights after reviewing held-out results without a new independent evaluation.
- At M4 record a real unseen query yielding five distinct eligible items with a reproducible trace, and a separate degraded query or error case. Retain commands, commit, real gallery/fit/extractor/metric profile IDs, screenshots or trace, result identities and exact-reference comparison. Label any fixture execution separately and exclude it from real acceptance and reported quality metrics.
